# 01 需求

## 用户、目标与范围

用户是运营人员：给出主题、模拟预算和截止时长，希望获得可执行内容活动方案，或明确的未完成原因、缺失输入、费用/时间缺口。

输入为 topic、budget、deadline（模拟分钟）。输出为 RunState JSON、方案步骤及依赖、每步状态和工具结果、当前方案报价、费用台账、保存文件与 Trace。工具仅处理 data 中的合成素材并写本地文件。真实模型使用 OpenAI 兼容接口；离线模型是明确标注的脚本策略。

## 成功标准

1. 真实模型每轮返回 action/args/rationale JSON，根据 observation 选择下一步。代码不得自动重试或替模型规划。
2. 无效动作、依赖不满足和工具错误都回传 observation；失败记录不能改成成功。
3. 状态每次转移落盘，成功结果可复用；续跑不重做已成功步骤，Trace 标明复用。
4. 所有总额由代码从工具报价组件求和；保存前再次校验预算、模拟时间及估算新鲜度。
5. 预算 10 时 full 报价 12，调整脚本后重新报价 8，才能保存；最低报价高于约束时返回缺口。
6. 缺预算/时限返回 needs_input 且工具调用为 0。
7. 相同请求和内容只保存一份；第二次费用台账增加 0，不改写原文件。
8. 默认 12 轮与 12 次工具上限；终止时保留成功结果。
9. 每个验收场景都有测试和真实执行证据；不将 Mock 证据宣称为 LLM 决策效果。

## 边界

时间使用模拟时长，不接收日历时间点。报价采用免费规划、保存提交模型，详见 README；并非每次工具预览付费。真实 API 费用独立。个人经历、个人修改与学习体会由提交者填写，不由 AI 代编。
