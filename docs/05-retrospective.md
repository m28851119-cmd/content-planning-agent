# 05 复盘

## 实现中最难的问题（基于本次代码与验证）

1. **计费语义**：如果把废弃脚本预览的报价计为实际支付，12 → 8 的参考路径不可能满足预算 10。实现明确采用预览报价、保存提交模型，并保留全部报价历史。
2. **失败与续跑**：失败尝试必须保留；重试创建新步骤，不能将原失败覆盖。成功结果作为依赖复用，恢复不重做检索。
3. **保存边界**：文件提交成功后进程可能在状态落盘前中断。通过稳定幂等键、原子不覆盖提交和 run 收据重建台账，测试模拟了这个窗口。
4. **真实模型与 Mock 的区别**：真实模型最初直接选 lite，不能把它写成观察到 12 后重规划。保留原记录，在 prompt 中明确 full 质量基线偏好，再取得实际 12 → 8 的新 Trace。
5. **环境兼容性**：Windows 沙箱禁止硬链接，回归测试发现保存失败；使用 Windows rename 的禁止覆盖语义修正，POSIX 保留 hard-link 发布策略。

## 从实现可以提炼的工程结论

确定性约束必须落在代码里；模型做决策，不能充当账本。错误是下一轮输入的一部分。测试策略能证明执行器行为，但不能代替真实模型评测。状态持久化不等于外部副作用恰好一次，需要单独处理提交窗口。

## 下一步候选

增加真实模型多种子评测、token 成本和延迟统计、schema constrained decoding、可验证的素材质量约束、数据库事务和并发 run 锁。若改为每次工具调用都收费，应重新定义规划策略和预算参考用例，不能继续沿用当前免费预览口径。
